生成讲义、任务卡或审查课程时读。具体进度以 `LEARNING_PROGRESS.md` 为准，本文件只管交付质量，不保存日程，也不提供当前作业答案。

## 一、交付清单

| 项目 | 必须说明 |
|---|---|
| 主要目标 | 本单元解决什么问题；哪些是辅助，哪些是选学 |
| 前置 | 用到哪些已学内容；新引入的对象、参数、返回值的实际类型 |
| 调用链 | 启动命令 → 入口 → 调用的函数 → 返回 → 显示；谁创建、谁关闭资源 |
| 学员任务 | 要实现的接口或需求、输入输出、允许修改的范围；TODO 保留位置 |
| 文件 | 随课样本、运行产出、临时验证文件分别放在哪 |
| 环境 | 解释器、依赖、启动目录与命令；Windows 路径写法 |
| 验收 | 固定样本与可人工核算的预期；正常、边界、关键失败三类 |
| 节奏 | 大约需要几次课；前置可跨日，不按编号硬赶 |

**通过标准与提交清单必须分离**：提交清单里每一项如果要算门槛，必须在“通过标准”里同样出现；否则检查时不得据此判不通过。标准发布后如需补充，写清日期与是否追溯。

## 二、发布前必须实际执行

0. **前置与阅读审查**：列出本课每个新语法；不能用“只学数据形状”掩盖多个新操作。只读主讲义和单文件演示也能解释输入、状态变化、结果，无需跳文件。新手先少量干净样本，脏数据到对应校验课再引入。

1. **独立算预期值**。不能拿被测实现的输出当"预期"，要按样本手工核算一遍。
2. **复制单元目录到 `_work\<unit>\` 再跑**，确认不依赖旧单元文件、不依赖绝对路径、不依赖当前 shell 的工作目录。
3. **讲义里每段命令都跑一遍**。有意设计的失败演示要在讲义里说明"这是故意的，期望看到 X 报错"。
4. **区分 TODO 未完成与真实错误**：`NotImplementedError`、留空的返回值属于待完成；缺样本、路径错、依赖缺失属于必须修。
5. **样本与产出隔离**：产出写 `out/`（已在 `.gitignore`），不覆盖输入样本。
6. **两条运行路径都验证**：终端 `cd unitNN` + `python x.py`，以及项目根 `python unitNN\x.py`。按钮行为取决于配置，不能声称等价；新检查只用于当前课程交付。

## 三、本项目高频错误点（写讲义时逐条对照）

按当前任务选择适用项，不要求变量课同时理解下面所有内容。它们是教师的质量清单，不是新增学员通过标准。

- **CSV字段**：普通字段通常为字符串；缺列可为None，多列可在默认None键下形成列表。数值转换需在明确数据约定下进行；第一次演示只用干净样本。
- **`csv.DictReader`**：缺列（值为 `None`）、多列（进 `restkey`）、空行、BOM、GBK 编码样本
- **字典键**：大小写、首尾空格、列名拼写；`KeyError` 与 `.get()` 的区别
- **路径**：`pathlib` vs 字符串拼接；中文路径；从项目根与从单元目录启动的差别
- **退出码**：正常 0；`sys.exit(1)`；未捕获异常默认 1；只看打印不看退出码是运维工具的典型缺陷
- **编码**：Windows 控制台代码页；UTF-8 与 GBK 样本；`open()` 的 `encoding=` 参数
- **psutil**：字节单位换算、Windows 与 Linux 指标语义差异
- **socket**：超时、连接被拒、DNS 解析失败要分开处理，不能都算"不通"
- **并发**：线程池数量、超时、结果顺序、异常吞掉
