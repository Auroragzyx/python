# 作业验收

## 准备

读 `TEACHING.md`、`LEARNING_PROGRESS.md` 顶部状态、当前单元 `task.md`、学员代码和 `samples/`。
**以任务书里的"通过标准"为唯一门槛**：不临时加要求，不把以前的额外挑战追溯成这次不合格。

## 运行环境

- 项目根、解释器与依赖以当前SETUP及实测为准，不写死E盘、版本或旧U5时间点。
- 把单元目录复制到 `_work\<unit>\` 再跑，或用临时目录；**不改原文件、不污染 samples/**
- 两条路径都要跑：
  1. 终端：`cd unitNN_xxx` → `python xxx.py`
  2. 项目根：`python unitNN_xxx\xxx.py`；按钮行为另按实际配置观察，不能宣称严格等价。
- 记录退出码（PowerShell 里 `$LASTEXITCODE`），不只看打印内容

## 检查项

下面是教师按原题适用性选择的检查维度，不是每次新增的门槛。变量课不验CSV、IP、编码或并发；注释骨架退出0却无预期输出仍是待完成。历史原题与新路线分别记录，不回溯增加标准。

| 类别 | 具体检查 |
|---|---|
| 正常路径 | 按固定样本跑，结果条数/统计值可人工核算 |
| 边界 | 空文件、缺列、重复主机名、0 条命中、超长字段 |
| 关键失败 | 文件不存在、编码不对、字段类型错、路径从错误目录启动 |
| 资源与副作用 | 是否改动输入样本、重复运行结果是否一致、有无未关闭的文件 |
| 环境 | 中文是否乱码、有无硬编码绝对路径 |

## 报告格式

按任务书条目逐条列：**需求 → 预期 → 实际 → 结论**。分开三类：

- **阻塞**：核心要求没达到，必须改
- **功能错误**：能跑但结果不对
- **建议**：不影响通过，最多两条，不追加为门槛

指导修改时给：文件名、当前行号、相关原代码、最小修改方向、原因。默认**不改文件**；学员明确说"帮我改"才动手，并在 `LEARNING_PROGRESS.md` 记录"AI 代改"。

## 诚实性

- 没运行 = 没验证，直接说明
- 在副本里修好 ≠ 原作业通过
- 环境问题（缺依赖、路径、编码）与学员代码错误分开报
- 学员查资料不算"不会"，闭卷回忆另行安排

## 记录

写入 `LEARNING_PROGRESS.md`：是否通过、是否独立完成、帮助程度（无 / 提示 / 参考示例 / AI 代改）、待复测项。
**未通过不开下一课**；非阻塞建议不无限拖延推进。
