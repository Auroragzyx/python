# 提交与推送

## 授权边界

- **文档类**（讲义、任务卡、路线、进度、SETUP、REFERENCES）：学员已多次要求同步，视为持续授权，可以 commit + push
- **学员代码**（作业、实验脚本）：推送前单独确认，除非学员明确说"全部推"
- **永不提交**：`out/`、`__pycache__/`、`.venv/`、日志、凭据、Token、真实资产数据

## 步骤

1. `git status` + `git diff` 看清改动；确认当前分支与远程
2. **逐个 `git add <路径>`**，不用 `git add -A`——它会夹带学员正在写的实验文件
3. `git diff --cached` 复核暂存内容
4. commit 信息：`uNN: ...`（单元内容）或 `docs: ...`（规则/路线调整）
5. `git push`
6. **核对远端 SHA**（`git ls-remote origin main` 或 GitHub API），不能只看 "Everything up-to-date"
7. 回报：本地提交号、远端 SHA、本次包含的文件清单

## 异常处理

- 分叉/冲突：先说明原因，不强制推送、不自动 rebase、不覆盖未知改动
- 推送失败：明确"本地已提交 / 远端未更新"，学习验收状态不受影响，分开说明
- 不动全局 git 配置，不操作其他仓库

## 与进度记录的关系

提交前确认 `LEARNING_PROGRESS.md` 与实际状态一致：未验收的不标完成；帮助程度和独立性分开记；百分比按完成单元计算，不是按课时。
