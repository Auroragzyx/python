## 本课解决什么问题

你现在有两个文件：`SETUP.md` 里写的安装步骤、`task.md` 里写的任务。这一课要打通一条链路：

**你在终端敲一条命令 → Windows 找到 python.exe → 解释器读你的 .py 文件 → 一行一行执行 → 结果打到屏幕上。**

这条链路以后每天都用。链路里任何一环断了（找不到 python、文件路径不对、代码写错、中文乱码），现象不同，排查位置也不同。本课就是把这四种故障各见一次。

本课不讲函数、不讲循环，只有一个新东西：**print 和表达式**，其余时间都在认路。

## 按执行顺序看

### 1. 启动命令

```powershell
cd E:\python\unit00_env
python hello.py
```

`python` 是命令，`hello.py` 是参数。Windows 先在自己的 PATH 里找 `python.exe`；找不到就报
`无法将"python"项识别为 cmdlet...`——这是**环境问题**，不是代码问题。

`cd` 只是切换当前目录。`python hello.py` 里的 `hello.py` 是**相对路径**，相对于你当前所在目录。所以在 `E:\python` 下敲 `python hello.py` 会报找不到文件。

在 VS Code 里，这条命令敲在**内置终端**里（按 `` Ctrl+` `` 打开，反引号键在 Tab 上方）。它跟外面的 PowerShell 是同一个东西，只是嵌在编辑器下方。两点区别：

- 终端启动时的当前目录，取决于你用"打开文件夹"打开的是哪个目录；如果只打开了单个文件，目录往往不是你以为的那个。
- 点右上角 ▷ 运行时，VS Code 从**项目根** `E:\python` 启动终端，所以脚本里的相对路径按项目根算，不是按脚本所在目录算。这个差别在 U1 读 CSV 时会真的踩到。
- VS Code 不会自动保存。改完代码要按 `Ctrl+S`，否则 `python hello.py` 读到的还是磁盘上的旧内容，你会以为"改了没用"。

### 2. 程序入口

一个 .py 文件就是一个从上往下顺序执行的脚本，没有 `main` 函数也能跑。解释器从第 1 行开始，一行一行往下走，走到文件末尾就退出，退出码 0。

### 3. 准备数据

本课没有外部数据，所有数据都写在源码里：

```python
print("桌面运维 - 张三")
```

括号里的 `"桌面运维 - 张三"` 是**字符串**（`str`），带引号，英文引号。引号本身不打印，它只是告诉 Python "这里面是文字"。

```python
print(2 + 3 * 4)
```

这里的 `2`、`3`、`4` 是**整数**（`int`），没有引号。没有引号的数字才能参与计算；`"2" + "3"` 是字符串拼接，结果是 `"23"`，这是后面单元会踩的坑。

### 4. 调用函数

`print` 是 Python 自带的函数。你给它一个值，它把这个值转成文字送到屏幕。它返回 `None`（没有返回值），所以 `x = print("hi")` 之后 `x` 是 `None`。

### 5. 接收返回值

本课不接收返回值，只看屏幕输出。区别要记住：**print 是把东西显示出来，不是把东西存起来**。

### 6. 检查或显示结果

`2 + 3 * 4` 先算乘法：`3 * 4 = 12`，再算加法：`2 + 12 = 14`。所以输出 `14`，不是 `20`。
如果你想要 20，得写 `(2 + 3) * 4`。括号改变计算顺序，跟数学一样。

**常见错误：括号放错位置**

```python
print(2 + 3) * 4      # 错
print((2 + 3) * 4)    # 对，输出 20
```

第一种实际运行时先打印 `5`，然后报错：

```
TypeError: unsupported operand type(s) for *: 'NoneType' and 'int'
退出码: 1
```

因为 `print(2 + 3)` 已经执行完并返回 `None`，接着拿 `None * 4` 就出错了。顺序证明：**先打印了 5，再报错**，说明函数先跑完了。

`print(...)` 这对括号是"函数调用的括号"，不是数学括号；括号外面的 `* 4` 没有被交给 print。想先算完再打印，就把整个算式放进这对括号里。

等价的、更清楚的写法（U1 起常用）：

```python
result = (2 + 3) * 4
print(result)
```

### 7. 关闭资源

本课没有打开文件、没有连接、没有启动子进程，所以**没有需要关闭的东西**。解释器读完文件就结束，系统自动回收内存。

以后凡是有"打开"的动作（文件、数据库连接、网络会话、子进程），教案都会明确写：谁打开、谁关闭、什么时候关。

## 内存和磁盘的区别（本课唯一要建立的直觉）

- `hello.py` 这个文件在**磁盘**上，路径 `E:\python\unit00_env\hello.py`
- 你运行它时，内容被读进**内存**，解释器在内存里执行
- `print` 的结果只在**屏幕**上，程序结束就没了，磁盘上没留下任何东西

想让结果留下来，得写入文件——那是 U2 的内容。

## 故意搞坏一次：怎么读报错

删掉一个右括号后运行，会看到类似：

```
  File "E:\python\unit00_env\hello.py", line 3
    print(2 + 3 * 4
         ^
SyntaxError: '(' was never closed
```

三部分，从上往下读：

1. **位置**：`File "...hello.py", line 3` —— 哪个文件、第几行。这里给的行号通常准，但有时会指向"问题被发现的地方"，不一定是真正写错的地方。
2. **现场**：出错那一行原文，下面 `^` 指着解释器看不懂的位置。
3. **类型 + 消息**：`SyntaxError` 是错误类别，`'(' was never closed` 是具体原因（左括号没闭合）。

在 VS Code 里，`File "...", line 3` 这一行可以 `Ctrl+单击` 直接跳到出事的位置，比在终端里翻屏快得多。这也是用编辑器学习的一个实际好处——但跳过去之后，还是得自己判断哪里错了。

`SyntaxError` 的特殊之处：它在**读文件阶段**就报，代码一行都没执行。所以哪怕你前面写了三行正确的 print，也一个字都不会输出。相对地，运行时错误（如 `NameError` 用了没定义的变量）会先执行完前面的行再报。

常见的几类，先认脸，不要求背：

| 报错 | 中文意思 | 通常原因 |
|---|---|---|
| `SyntaxError` | 语法错误，解释器读不懂 | 括号/引号没配对、少了冒号 |
| `NameError` | 这个名字没定义 | 变量名拼错、用了没赋值的变量 |
| `FileNotFoundError` | 找不到文件 | 路径错、当前目录不对 |
| `IndentationError` | 缩进不对 | 空格和 Tab 混用、该缩进没缩进 |

## 中文乱码

Windows 控制台默认代码页是 GBK（936），Python 输出 UTF-8 中文时就会显示成 `����`。
解决：`setx PYTHONUTF8 1`，然后**关掉窗口重开**。这条设置写进用户环境变量，以后所有 Python 进程都按 UTF-8 处理。

如果只是临时看一次，也可以在 PowerShell 里先执行 `chcp 65001`，但那只对当前窗口有效。
